# 示例：AI 搜索竞品调研

## 用户可能的请求

```text
我要做 AI 搜索产品竞品调研，竞品包括豆包、通义千问、DeepSeek、ChatGPT 和小爱，目标是为后续搜索体验和 prompt 优化找方向，最后输出 Markdown/飞书报告。
```

## 应触发的处理方式

1. 先确认调研目标、时间范围、输出形式和是否已有材料。
2. 默认走公开资料调研主线，不直接进入 case 测试。
3. 将“体验”理解为公开用户反馈和市场感知，不等于亲自测试。
4. 如用户明确要比较真实回答策略，再进入可选 case 测试模块。

## 可能的功能矩阵维度

| 维度 | 说明 |
|---|---|
| 联网搜索 | 是否支持联网、是否默认启用 |
| 来源引用 | 是否展示来源、来源是否可追溯 |
| 搜索结果整合 | 是否能整合多来源，而非简单罗列 |
| 深度研究 | 是否有独立深度研究/长任务模式 |
| 回答模式控制 | 是否有快答/深度/推理/简洁模式 |
| 多轮追问 | 是否能围绕搜索结果继续追问 |
| 多模态搜索 | 是否支持图片、文件、截图等输入 |
| 语音/车端适配 | 是否适合短句、车载、安全场景 |
| 个性化/记忆 | 是否结合用户偏好或历史 |

## 公开体验反馈分析方向

| 主题 | 可观察材料 |
|---|---|
| 信息可信度 | 用户是否提到来源清楚、敢不敢信 |
| 信息新鲜度 | 是否吐槽过时、是否夸实时 |
| 信息组织 | 是否觉得结构清楚、是否吐槽堆内容 |
| 搜索效率 | 是否减少用户自己多次搜索 |
| 入口可见性 | 用户是否知道搜索/深度研究入口 |
| 结果可用性 | 是否能直接用于决策、购物、出行、学习 |
| 车端/语音适配 | 是否适合短句播报、是否过长 |

## 可能的调研结论形式

```text
事实依据：某些竞品近期强化搜索、深度研究或来源展示。
公开观察：用户更容易感知“来源清楚”“答案结构好”“能直接做决策”的产品价值。
分析判断：AI 搜索竞争不只是有没有联网，而是搜索整合、来源表达、信息层次和后续引导共同决定体验。
取长：优先补足用户可感知的信息组织和可信表达，而不是只堆搜索能力。
补短：{{竞品共同没做好的，有机会超越}}
避坑：{{竞品失败/收缩路径，要规避}}
待验证点：是否需要通过统一 case 测试验证真实回答策略差异。
```

## 如进入 case 测试

先共同确认场景，不直接定稿。候选场景可以包括：

- 时效事实搜索；
- 购买/选择决策；
- 医疗/安全边界信息；
- 本地生活/出行；
- 多轮追问；
- 车端语音短句场景。

输出必须标注为测试集草案，并让用户确认保留、删除、替换或加入业务真实问题。
