# 示例：AI 陪伴产品竞品调研

## 用户可能的请求

```text
我想调研 AI 陪伴类产品，比如豆包角色、星野、Talkie、Character.AI，看看它们在功能、用户口碑和产品定位上有什么差异。
```

## 应触发的处理方式

1. 确认调研用途：产品规划、功能参考、口碑分析、汇报材料或人设策略优化。
2. 默认基于公开资料和公开用户反馈做调研。
3. 不直接评价真实陪伴体验，除非用户提供测试材料。
4. 不固定使用通用问答策略维度，应围绕陪伴产品动态生成维度。

## 可能的功能矩阵维度

| 维度 | 说明 |
|---|---|
| 角色创建 | 是否支持自定义人设、外观、背景 |
| 角色市场/社区 | 是否有角色广场、UGC、分享机制 |
| 长期记忆 | 是否记住用户偏好、关系进展、历史事件 |
| 主动消息 | 是否主动触达、触发条件是什么 |
| 语音/通话 | 是否支持语音聊天、实时通话、音色 |
| 多模态 | 是否支持图片、表情包、视频理解 |
| 情绪识别 | 是否识别用户情绪并调整回复 |
| 关系推进 | 是否有亲密度、剧情、长期陪伴机制 |
| 安全边界 | 是否处理依赖、心理风险、未成年人问题 |
| 商业化 | 会员、道具、角色付费、增值服务 |

## 公开体验反馈分析方向

| 主题 | 可观察材料 |
|---|---|
| 陪伴感 | 用户是否说“像真人”“被理解”“有陪伴” |
| 人设稳定性 | 是否吐槽角色崩、前后不一致 |
| 情绪价值 | 是否有安慰、鼓励、缓解孤独等反馈 |
| 沉浸感 | 是否提到剧情、语音、角色设定有吸引力 |
| 边界问题 | 是否出现过度依赖、擦边、安全风险吐槽 |
| 付费感知 | 是否吐槽贵、限制多、诱导付费 |
| 社区传播 | 用户是否分享角色、对话截图、玩法 |

## 可能的调研结论形式

```text
事实依据：竞品在角色创建、主动消息、语音和社区方面形成不同功能组合。
公开观察：用户更容易传播具有强人设、强情绪价值或强剧情沉浸感的产品体验。
分析判断：AI 陪伴产品竞争不只是模型会聊天，而是角色设定、长期记忆、情绪回应、关系机制和安全边界共同构成体验。
取长：若要进入陪伴场景，需要明确是做轻陪伴、角色娱乐，还是心理支持型陪伴，不宜只复制单个功能。
补短：{{竞品共同没做好的，有机会超越}}
避坑：{{竞品失败/收缩路径，要规避}}
待验证点：公开口碑是否能代表长期留存体验，需要结合真实用户访谈或 case 材料验证。
```

## 如进入 case 测试

先共同确认测试目标，例如：

- 测角色一致性；
- 测情绪安抚；
- 测长期记忆；
- 测边界处理；
- 测主动陪伴。

case 必须先作为草案输出，让用户确认是否贴合目标人群和产品定位。
